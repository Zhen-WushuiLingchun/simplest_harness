## 1. 科学目标

在 DeepSWE v1.1 的一个小型、跨仓库、跨语言和跨任务类型的固定任务集中，估计：

> 通过 DeepSeek 官方 OpenAI-compatible API 调用同一公开模型名
> `deepseek-v4-flash` 时，TMSH `33cf1b975f97e77f87868a2189758d8dd4127520`
> 相对官方公开 `mini-swe-agent + deepseek-v4-flash[max]` 的逐题通过率差异。

本实验测量的是 **harness + resident prompt + 工具接口 + 上下文管理** 的组合差异，
不是重新估计模型本身的 113 题总榜能力，也不证明两个 harness 等价。

## 2. 已知事实、假设与边界

1. DeepSWE v1.1 有 `113` 题、`91` 个仓库、`5` 种语言；官方榜单统一使用
   `mini-swe-agent`。公开任务定义固定到上游 commit，并由行为 verifier 评分。
2. DeepSeek 官方文档在冻结时把 API 别名 `deepseek-v4-flash` 标为
   `DeepSeek-V4-Flash-0731`，上下文 `1M`，最大输出 `384K`。
3. 公开对照配置是 `mini_swe_agent_deepseek_v4_flash_max`，共
   `452=113×4` 个计分 trial，公开总体为 `241/452=0.5331858407079646`。
4. 相同公开模型名和版本标签不等于可证明的逐字节相同服务端权重、采样实现或
   调度环境。公开 trial 运行于 `2026-08-05` 至 `2026-08-06`，TMSH trial 将晚于该时间；
   这项时间漂移风险必须保留。
5. 两边没有共同随机种子，四次 attempt 不能按顺序一一配对；只比较每题四次
   pass 数和由此得到的通过率。
6. DeepSWE 网络策略只允许模型 API；TMSH 的联网调研能力在正式 trial 中不可用。
   这不是基础设施故障，而是共同 benchmark 约束下的可观察 harness 行为。
7. DeepSeek context cache 默认启用并按完整前缀匹配，但属于 best effort；不能
   预先假定命中率。公开数据与 TMSH 数据中的 hit/miss token 必须分开报告；缺失值
   保持缺失，不以估算值冒充观测值。

## 5. 零付费基础设施门禁

在任何正式模型 trial 前，必须按冻结任务集依次完成：

1. **Oracle gate**：每题一次 reference solution，要求 `20/20` 完成、Pier exception
   `0`、每题 Reward 精确为 `1.0`。
2. **Nop gate**：每题一次空补丁，要求 `20/20` 完成、Pier exception `0`、每题
   Reward 精确为 `0.0`。若某题空补丁通过，整个预注册集失败，不事后换题。
3. **Adapter gate**：Agent image 必须报告 TMSH commit 精确匹配、Node
   `24.19.0`，并能在不读取/打印 Key 的情况下访问模型 endpoint。
4. 任一 gate 失败时，不启动正式 `80` 个 trial；保留失败证据，修复后必须发布
   preregistration amendment，而不是覆写 v1。

门禁和正式运行均通过前台阻塞式 PowerShell runner 执行；`-Quiet` 时仅在终态输出
`CAMPAIGN_TERMINAL`，不使用 heartbeat 或按时间轮询模型来消耗额外上下文。

## 6. 计分、失败和重试规则

每题需要四个 **计分 attempt**：

- verifier 正常产出 Reward `0` 或 `1`：计入；Reward `0` 不得重试。
- TMSH 达到 `maxModelCalls=200`、上下文上限或自身 agent timeout：这是 harness
  资源边界，计作 Reward `0`，不能作为基础设施异常排除。
- 明确的 provider 5xx/429、DNS/网络、Pier/verifier exception、损坏的环境构建：
  不计入能力分母；只补足缺少的计分 attempt，并完整保留无效 attempt。
- 每题最多允许 `2` 个基础设施替代 attempt。超过后该题和总比较均标为
  `INCOMPLETE`，不更换任务、不输出选择性总体胜负。
- 任何异常分类必须在查看该 trial 的模型 Reward 之前，仅根据异常类型与终态决定。

## 7. 统计量与报告格式

令 `T_i` 为 TMSH 在第 `i` 题的四次通过数，`P_i` 为公开 mini-swe-agent 的四次
通过数。主统计量预注册为：

`D = (1/20) * sum_i[(T_i/4) - (P_i/4)]`

即等权任务平均通过率差，单位为百分点。必须同时报告：

- 20 行逐题表：公开四次 trial ID/reward 向量、TMSH 四次 trial ID/reward 向量、
  `T_i-P_i`；
- 总通过数、`D`、逐题 win/tie/loss；
- task-cluster bootstrap `100000` 次、seed `20260812` 的描述性 `95%` 区间；
- F2P、P2P、Partial，不用模糊文字替代任何数值；
- provider/网络/verifier 无效 attempt 数及精确原因；
- 模型请求/响应、工具调用/结果、input/output/peak tokens、压缩次数、修改文件、
  git 状态和 wall time；
- `prompt_cache_hit_tokens`、`prompt_cache_miss_tokens` 和费用仅在真实数据可得时报告；
  缺失不得估算为观测值。

样本只有 20 个任务，本实验结果是有界校准，不外推为完整 113 题榜单，也不以
单个显著性阈值宣称普遍优越。

## 8. 已知风险和精确下一步

未解决风险：

- API 别名可能服务端漂移；只能冻结公开 build 标签，无法获得权重哈希。
- TMSH 当前 usage 事件只观测 input/output/total tokens，未保留 DeepSeek 响应中的
  `prompt_cache_hit_tokens` 与 `prompt_cache_miss_tokens`；因此 TMSH 的实际 cache
  费用目前不可直接从事件重建。
- 两个 harness 的 prompt、工具粒度和步骤语义不同；这正是实验变量，不应包装成
  纯模型比较。
- 任务 checkout 的 `tasks/README.md` 非 clean 状态必须保留，但不属于任何入选任务 tree。

精确下一验证步骤：**先提交本文件和 manifest 形成不可变选择时间点；随后才从官方
`trials.json` 提取这 20 题的 80 个公开对照并另行提交，再运行 Oracle gate。Oracle
未达到 `20/20` Reward `1.0` 且 exception `0` 前，不运行任何正式 DeepSeek trial。**
