# 预注册修订 1：benchmark adapter 与 validator

关联预注册：`2026-08-12-deepswe-v1.1-crossrepo20-preregistration.md`

任务选择 commit：`97eb649`

公开对照 commit：`58164c1`

本修订不改变任务、模型、provider、attempt 数、主要统计量、重试或失败分类。它在
正式 campaign 启动前修复两个 benchmark 侧问题，并增加一个纯观测字段：

1. `nvm install 24` 是浮动 minor/patch，不能满足预注册的 Node 精确冻结；改为
   `nvm install 24.19.0`，并在 install verification 中验证 Node、pnpm 与 TMSH commit。
2. Pier `result.json` 的一个 eval 只含一个聚合 metrics 对象；旧 validator 错误期待
   20 个 metrics 对象。修复后从 `reward_stats.reward` 的 trial ID buckets 计数，并
   增加 `-ValidateOnly` 以只读复核既有 job，避免为修 validator 重跑 benchmark。
3. 原冻结 TMSH `33cf1b975f97e77f87868a2189758d8dd4127520` 的 usage 事件不保留
   DeepSeek `prompt_cache_hit_tokens`/`prompt_cache_miss_tokens`，无法审计用户提出的
   KV cache 成本假设。TMSH commit 改为
   `709ed7905aea0ac95d4d9c5d094a7e1c9f0e406a`：它只把 provider 返回的
   cache read/miss/write token 写入 usage 事件，并让 Pier 汇总 `n_cache_tokens`；不改
   system prompt、模型消息、工具、采样、上下文阈值、资源上限或 verifier。

第 3 项在查看任何 TMSH 正式 20 题 reward 前完成。原 `33cf1b9` anko 校准结果不得与
本实验 `709ed79` 的 80-trial 分母合并。

`709ed79` 交付门禁：typecheck 通过，build 通过，`22` 个 test files / `66` tests
通过，format check 与 `git diff --check` 通过。动态 install smoke 观察到 Node
`v24.19.0`、pnpm `11.21.0`、TMSH `709ed7905aea0ac95d4d9c5d094a7e1c9f0e406a`、
`model_called=false`、exception `null`。
